# AVMS — Database Mapping (MySQL/Django ORM → Oracle)

## 1. Type map

| Django/MySQL | Oracle | Notes |
|---|---|---|
| `BigAutoField` PK | `NUMBER(19) GENERATED BY DEFAULT ON NULL AS IDENTITY` PK | Keep `id` names. |
| `CharField(n)` | `VARCHAR2(n)` | Django `max_length` preserved. |
| `TextField` | `CLOB` (or `VARCHAR2(4000)` where short) | description/notes. |
| `DecimalField(12,2)/(14,2)/(5,2)` | `NUMBER(12,2)` / `NUMBER(14,2)` / `NUMBER(5,2)` | Money/quantity exact. |
| `DateTimeField` | `TIMESTAMP` | `created_at/updated_at`; default `SYSTIMESTAMP`. |
| `DateField` | `DATE` | sale/purchase/payment/expense dates, attendance date. |
| `BooleanField` | `NUMBER(1)` check 0/1 | Hibernate maps automatically. |
| `EmailField` | `VARCHAR2(254)` + unique where applicable | — |
| Enums (status/type/method) | `VARCHAR2(30)` + `CHECK` constraint | Preserve Django `choices` values verbatim (e.g. `PENDING,PARTIAL,COMPLETED,RETURNED,CANCELLED`). |
| M2M join tables | Join tables with composite PK + FKs | `accounts_user_roles`, `accounts_role_permissions`, Django `groups/user_permissions` replaced by Spring model (drop `auth_group` unless needed). |
| `OneToOne` (Employee.user, StockMovement.paired) | `NUMBER(19)` unique FK | Same semantics (`SET_NULL` → `ON DELETE SET NULL`, use Hibernate `@OneToOne`). |

## 2. Table map (Django table → Oracle table, keys preserved)

- `accounts_user` → `ACCOUNTS_USER` (email unique; drop `groups/user_permissions` M2M unless Spring needs them — roles/permissions are the app model).
- `accounts_permission` → `ACCOUNTS_PERMISSION` (`code` unique, index `module`).
- `accounts_role` + `accounts_user_roles` + `accounts_role_permissions` → same names uppercased.
- `ventures_venture` → `VENTURES_VENTURE` (`venture_code` unique, index `status`).
- `core_sequencecounter` → `CORE_SEQUENCE_COUNTER` (unique `(module,venture_id)`); replaces `VentureCodeCounter` for all new codes (keep `VENTURES_VENTURECODECOUNTER` read-only compat during data migration, then retire).
- `customers_customer` → `CUSTOMERS_CUSTOMER` (unique `(venture_id,customer_code)`).
- `suppliers_supplier` → `SUPPLIERS_SUPPLIER` (unique `(venture_id,supplier_code)`).
- `products_unit` → `PRODUCTS_UNIT` (`unit_code` unique; global, no venture FK).
- `products_category` → `PRODUCTS_CATEGORY` (unique `(venture_id,category_name)`).
- `products_product` → `PRODUCTS_PRODUCT` (unique `(venture_id,sku)`; `category→SET NULL`, `unit→RESTRICT/PROTECT`).
- `inventory_warehouse` → `INVENTORY_WAREHOUSE` (unique `(venture_id,warehouse_code)`).
- `inventory_inventory` → `INVENTORY_INVENTORY` (unique `(warehouse_id,product_id)`).
- `inventory_stockmovement` → `INVENTORY_STOCKMOVEMENT` (self-FK `paired_movement_id`, `destination_warehouse_id` nullable).
- `purchases_*` (4) / `sales_*` (4) → same names uppercased; per-venture uniques on invoice/return numbers; `supplier/customer PROTECT→RESTRICT`, `warehouse→SET NULL`.
- `payments_payment` → `PAYMENTS_PAYMENT` (logical `(reference_type,reference_id)`, no DB FK; add composite index for lookups).
- `expenses_expensecategory|expense` → `EXPENSES_*`; seed 8 categories + 6 units via Flyway/Liquibase `V2__seed.sql` (mirrors Django data migrations).
- `employees_employee|attendance` → `EMPLOYEES_*`; uniques `(venture_id,employee_code)`, `(employee_id,att_date)`; `user_id` unique nullable FK.
- `audit_auditlog` → `AUDIT_AUDITLOG` (indexes `module`, `created_at`; `object_id VARCHAR2` generic).
- `notifications_notification` → `NOTIFICATIONS_NOTIFICATION` (index `(user_id,is_read,created_at)`).
- New: `REFRESH_TOKEN` (jti/hash, user_id, expiry, revoked) for rotation/blacklist; `PASSWORD_RESET_TOKEN` if not using stateless HMAC tokens.

## 3. Constraints / indexes to recreate

- All per-venture uniques, `Inventory(warehouse,product)`, `Attendance(employee,date)`, `SequenceCounter(module,venture)` (partial: `venture_id` nullable — Oracle allows multiple NULLs in unique, matching Django semantics; enforce single global row per module via application check or function-based index).
- All FK actions: venture FKs `CASCADE`; product category `SET NULL`; product unit / bill customer-supplier / expense category / return parent `RESTRICT` (Django PROTECT = block in app with 400 before DB); movement/return children `CASCADE`; `created_by/user` `SET NULL`.
- Indexes: `VENTURES_VENTURE(status)`, `ACCOUNTS_PERMISSION(module)`, `AUDIT_AUDITLOG(module, created_at)`, `EMPLOYEES_ATTENDANCE(att_date)`, payments `(reference_type,reference_id)`, stock movement `(venture_id, product_id, warehouse_id, movement_date)`.

## 4. Sequences / code generation

- Replace `SELECT FOR UPDATE` counter with same pattern in JPA: `SequenceCounter` row locked via `PESSIMISTIC_WRITE`, `nextValue+1`, format `PREFIX-%04d`. One row per `(module, venture)`; `V` module uses venture-agnostic global row.
- Oracle `IDENTITY` handles PKs; business codes remain application-formatted strings (never DB sequences) so `C-0001` semantics and no-reuse-after-delete are preserved.

## 5. Data migration rules

- Never destroy existing data: migrate via export (Django `dumpdata` or MySQL dump) → transform (lowercase table renames, `TINYINT→NUMBER(1)`, `DATETIME(6)→TIMESTAMP`) → load into Oracle; verify row counts per table + spot-check money/stock totals.
- Charset: MySQL `utf8mb4` → Oracle `AL32UTF8`.
- Timezone: Django `Asia/Kolkata` — store UTC `TIMESTAMP`, render IST in UI (existing behavior: naive server-local; document and keep UTC+IST conversion in Spring `spring.jpa.properties.hibernate.jdbc.time_zone=UTC`).
- Document every schema delta in `DATABASE_MIGRATION_NOTES` (this file's appendix) before applying.
